# Импорт из старой CRM

Перенос данных школы из выгрузок старой CRM: **Настройки → «Импорт из старой CRM»** (`/settings/import`),
API `POST /api/import/old-crm` (проверка) и `POST /api/import/old-crm?commit=true` (загрузка).
Код: `backend/app/modules/imports/` (`parse.py` — чтение файлов, `steps.py` — запись, `router.py` — API).
Старый импорт учеников из нашего шаблона (`/students/import`, `POST /import/students`) остаётся как был.

В этом документе нет ни одного реального имени, телефона или суммы: только устройство файлов и правила переноса.
Тесты (`backend/tests/test_old_crm_import.py`) строят маленькие синтетические файлы с той же разметкой.

## Как это работает

1. **Загрузка.** Можно сразу несколько файлов `.xlsx` и `.csv` (до `OE_IMPORT_MAX_MB`, по умолчанию 10 МБ каждый,
   до 20 файлов). CSV: разделитель `;` (или `,`), кодировка UTF-8 с BOM или Windows-1251. Файлы читаются только
   `openpyxl` (read_only, data_only — формулы не вычисляются) и `csv`, ничего из файлов не выполняется.
   Разбор идёт в отдельном потоке (`run_in_threadpool`).
2. **Тип файла** определяется по заголовкам (первые 10 строк: первой строкой выгрузки идёт название отчёта,
   заголовок — во второй). «Карта посещаемости» и «Расписание аудиторий» — не таблицы, их узнаём по названию и разметке.
   Тип можно поменять вручную для каждого файла.
3. **Проверка** (dry run) выполняет ровно тот же код, что и загрузка, внутри SAVEPOINT, который в конце откатывается.
   Поэтому проверка показывает то, что сделает загрузка: по каждой строке — «новая / обновится / пропуск / ошибка»
   с причиной, и итоги.
4. **Загрузка** идёт файл за файлом в порядке зависимостей, каждый файл — одна транзакция и одна запись в журнале
   действий (`import.commit`, с итогами). Каждая строка — в своём SAVEPOINT: ошибочная строка не записывается
   наполовину, остальные строки файла загружаются. Если файл упал целиком, откатывается только он.
5. **Порядок:** справочники (филиалы, уровни, аудитории — собираются из всех файлов) → преподаватели → группы →
   ученики (с родителями и местами в группах) → индивидуальные занятия → расписание аудиторий → посещаемость →
   платежи → книги → коммуникации.
6. **Повторная загрузка ничего не задваивает.** Каждая перенесённая строка помнит свой ключ в старой CRM
   (таблица `import_refs`: тип, внешний ключ, наша запись, отпечаток строки). Тот же файл ещё раз — все строки
   «пропуск: без изменений». Изменённая строка — «обновится» (например, изменился остаток ученика: проводится разница).
7. **Сопоставление с тем, что уже есть:** ученики — по ИД клиента (ключ), иначе ФИО + телефон (+7XXXXXXXXXX),
   без телефона — ФИО в том же филиале; сотрудники — по ФИО (полному или «Фамилия И.»); группы — по названию
   («834-B» латиницей и «834-В» кириллицей — одна группа, пробелы не важны); филиалы — по названию без учёта регистра;
   уровни — по названию с учётом опечаток старой CRM; аудитории — по названию или по номеру в том же филиале
   («room 3» = «Каб. 3»).
8. **Права:** новое действие `import.run` («Импорт данных → Импорт из старой CRM»), и только с охватом «сеть»:
   владелец или администратор сети. Миграция 0003 выдаёт его роли владельца.

### Деньги, сообщения, учётные записи

- Платежи переносятся **как история**: `payments.source = 'import'`, `is_first = false`, `lessons = 0`. Они не меняют
  баланс уроков, не дают бонусов и KPI (KPI считается только при приёме оплаты в системе), никому не отправляются
  WhatsApp-сообщения и уведомления. Принимавший в старой CRM записан в примечании; `received_by` — тот, кто
  импортировал.
- **Остаток ученика** берётся из старой CRM, а не пересчитывается по платежам и посещениям: «Приход» − «Расход»
  (личный счёт) минус оплаченные «Учебные материалы» этого клиента из файла платежей той же загрузки (см. вопрос 1).
  Остаток кладётся как денежный (`money_balance`) одной записью «Остаток на личном счёте в старой CRM».
  Уроков на балансе после импорта 0: в выгрузке нет колонки «осталось уроков» (вопрос 2).
- Отметки посещаемости переносятся **без списания уроков** (`charged = false`): баланс уже из старой CRM.
- Преподаватели создаются **без телефона и без пароля**: войти не могут, пока владелец не укажет телефон
  (в карточке сотрудника — только для тех, у кого его нет) и пароль. Паролей по умолчанию нет.
  Для этого `users.phone` стал допускать пустое значение (миграция 0003).
- Кабинеты учеников и родителей (вход по коду в WhatsApp) создаются только для тех, кто **занимается сейчас**.
  Код никому не отправляется, пока человек сам не запросит вход.

## Вопросы владельцу

1. **Остаток = «Приход» − «Расход» − книги.** В старой CRM оплата книг («Учебные материалы») попадает в «Приход», но не
   списывается в «Расход»: у 640 учеников остаток в точности равен их оплатам за книги. Мы вычитаем книги, чтобы не
   появились «лишние» деньги на счёте. Так верно? Остаток не нулевой после этого у 31 ученика.
